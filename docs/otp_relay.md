# OTP SMS 자동입력 — 중계기 구성 가이드

휴대폰인증 Run/Suite 가 `WAITING_INPUT` 으로 멈췄을 때, OTP 문자를 받는 휴대폰이 그 OTP 를
서버로 전달하면 사람이 개입하지 않고 자동으로 재개된다. **안드로이드는 "SMS 중계기"** 일 뿐이고,
E2E 엔진·대시보드는 서버(사내 PC/온프레미스)에 그대로 둔다.

이 문서는 **서버 엔드포인트 계약**과 **중계기 구성 방법**(앱 없이 빠르게 검증하는 길 → 필요 시
커스텀 앱)을 다룬다. 서버 측 설치/환경변수는 [../README.md](../README.md) 의 "선택 기능: OTP SMS
자동입력(중계)" 절이 단일 진실원천이다.

## 1. 서버 엔드포인트 계약

```
POST /api/otp/inbound
Header:  X-OTP-Relay-Token: <E2E_OTP_RELAY_TOKEN 와 동일한 값>
Header:  Content-Type: application/json
Body:    {"code": "123456"}            # 권장: 숫자 코드만
   또는  {"text": "[한화손해보험] 인증번호는 123456 입니다."}   # SMS 원문(서버가 정규식 추출)
```

동작:

- 서버는 `run_id` 없이 **현재 OTP 를 기다리는 Run 을 스스로 찾아** 코드를 주입하고 재개한다.
  개별 Run 이든 Suite 의 한 스텝이든 동일하게 처리된다(Run 재개 시 Suite 가 자동 반영).
- `code` 가 오면 그대로(4~8 자리 검증), 없으면 `text` 를 `E2E_OTP_RELAY_REGEX`(미설정 시
  `(\d{4,8})`)의 첫 캡처 그룹으로 추출한다.
- OTP 는 저장하지 않고 살아 있는 브라우저 세션에 즉시 주입 후 버린다.

응답:

| 상태 | 의미 | 중계기 처리 권장 |
| --- | --- | --- |
| `200 {"run_id","status"}` | 대기 Run 에 주입·재개 성공 | 정상 |
| `400` | 유효한 OTP 코드를 못 찾음(형식 위반/정규식 불일치) | 정규식/발신자 필터 점검 |
| `401` | 토큰 누락/불일치 | 토큰 재확인 |
| `404` | 지금 OTP 를 기다리는 Run 이 없음 | 무시(정상일 수 있음 — 이미 재개됐거나 점검 중 아님) |
| `503` | 기능 비활성(`E2E_OTP_RELAY_TOKEN` 미설정) | 서버 설정 점검 |

> 무인 점검은 순차 실행이라 보통 대기 Run 은 1건이다. 여러 건이면 가장 최근에 OTP 입력 대기에
> 들어간 Run(방금 도착한 SMS 에 대응)에 제출하므로, 휴대폰인증 점검은 `E2E_RUN_CONCURRENCY=1`
> 로 순차 실행하길 권장한다.

## 2. 중계기 구성

### 2-A. 빠른 검증 — 기존 문자 포워더 앱 (앱 개발 0)

먼저 앱을 만들지 말고, 시중의 SMS 포워더(예: MacroDroid, Tasker, "SMS Forwarder" 류)로 서버
경로 전체를 검증한다.

1. OTP 를 받는 그 번호의 SIM 이 꽂힌 안드로이드 폰에 포워더 앱 설치.
2. 트리거: **수신 SMS**(가능하면 발신자/키워드로 OTP 문자만 필터).
3. 액션: HTTP **POST** `http://<서버>:2222/api/otp/inbound`
   - 헤더 `X-OTP-Relay-Token: <토큰>`, `Content-Type: application/json`
   - 본문 `{"text": "{{sms_body}}"}` (앱이 본문 변수를 치환). 앱이 정규식 추출을 지원하면
     숫자만 뽑아 `{"code": "{{추출값}}"}` 로 보내도 된다.
4. 휴대폰인증 Run 을 띄워 `WAITING_INPUT` 까지 보낸 뒤, 실제 OTP 문자가 오면 자동 재개되는지 확인.

### 2-B. 운영용 — 커스텀 안드로이드 중계 앱 (선택)

포워더로 검증이 끝난 뒤, 더 정밀한 제어(발신자 화이트리스트·재시도·상태표시)가 필요하면 최소
기능의 커스텀 앱으로 대체한다. 핵심 요건만:

- `RECEIVE_SMS` 권한 + `SMS_RECEIVED` BroadcastReceiver 로 수신 가로채기.
- 발신자/키워드 필터 → 정규식으로 OTP 추출(또는 원문 그대로 전송).
- `POST /api/otp/inbound` 에 토큰 헤더로 전송, 실패 시 짧은 재시도.
- 설정 화면: 서버 URL · 토큰 · 발신자 필터 · 정규식.
- 안정성을 위해 포그라운드 서비스, 배터리 최적화 예외.
- 배포는 사내 **사이드로드**(플레이스토어 정책 무관). 빌드/서명은 Android Studio 에서 수행한다.

## 3. 보안·운영 메모

- 토큰이 유출되면 누구나 대기 Run 에 임의 코드를 주입할 수 있다. 토큰은 길고 무작위하게,
  비밀로 관리한다.
- 폰이 사내망 밖(셀룰러)에서 서버로 보내야 하면 평문 HTTP 대신 **TLS/VPN** 으로 전송 구간을 보호한다.
- 카카오인증은 휴대폰 카카오톡에서 사용자가 직접 승인해야 하므로 이 중계로 자동화되지 않는다.
  무인 100% 자동화는 **휴대폰인증** 에서만 가능하다.
