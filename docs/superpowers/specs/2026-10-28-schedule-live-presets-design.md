# 예약 실행 시 최신 프리셋 참조

## 목적과 확정 요구

프리셋에 새 입력값을 추가하거나 인증값을 수정하면 기존 예약의 다음 실행에도 반영한다. 사용자는 예약을 삭제하고 다시 등록할 필요가 없어야 한다. 사용자가 요청한 접근법은 예약이 현재 프리셋을 참조하는 방식이다.

## 접근법

- **채택: 프리셋 ID 참조 및 실행 시 조회.** 수정 시 예약들을 일괄 갱신할 필요가 없고, 현재 프리셋이 입력값의 기준이 된다.
- 비교: 프리셋 저장 시 연결된 예약의 복사본을 갱신하는 방식은 중간 실패와 동기화 누락을 처리해야 한다. 현재 프리셋을 직접 바라보라는 요청에 따라 채택하지 않는다.

## 데이터와 실행

1. 단일 시스템 예약에는 `preset_id`, 수트 예약에는 시스템 코드별 `preset_ids`를 저장한다. 프리셋 소유자는 예약 생성자이며, 관리자 대리 실행도 그 소유 관계를 바꾸지 않는다.
2. 등록·변경 때 프리셋의 소유자와 시스템 코드를 검증한다. 프리셋을 참조하는 예약은 인증값 복사본을 실행 입력으로 사용하지 않는다.
3. cron, 즉시 실행, 모바일 실행 모두 동일한 서비스 경로에서 최신 프리셋을 조회한다. 수트는 시작 시 선택된 시스템 전체의 프리셋을 조회·검증한 후 실행 입력을 확정한다.
4. 실행이 시작된 후에는 기존 Run/Suite 입력 스냅샷을 사용한다. 실행 도중 프리셋 수정, OTP 재개, 재시도가 실행 대상을 바꾸지 않도록 한다.
5. 이번 변경은 인증 입력값의 최신화가 범위다. 예약의 실행 시스템·모듈 선택과 브라우저 모드는 예약 설정을 유지한다. 단일 예약의 브라우저 모드도 프리셋과 분리해 보존한다.
6. 프리셋 삭제·소유자 불일치·시스템 불일치 시 실행을 중단하고 한국어로 재연결 필요 사유를 표시한다. 예전 인증값으로 자동 회귀하거나 다른 프리셋을 임의 선택하지 않는다. 일부 시스템 실행 후 참조 오류가 발생하는 일을 피하도록 시작 전에 검증한다.
7. 자동 실행에서 참조 오류가 발생해도 다른 예약 실행을 방해하지 않는다. 예약에 최근 실행 준비 오류를 남겨 목록·상세·모바일 상태에 표시하고, 다음 cron 시각을 정상 갱신한다. 재연결 또는 정상 실행 준비 시 오류 상태를 해제한다.

## 기존 예약 전환

기존 예약에는 프리셋 ID가 없으므로 등록 당시 대상의 추정이 필요하다. 다음은 구현자가 제안하는 정책이다.

- 동일 소유자·동일 시스템의 프리셋만 후보로 삼는다.
- 예약에 저장된 비어 있지 않은 인증 입력값 전체가 프리셋 값과 일치하는 후보를 찾는다. 브라우저 모드와 폼의 예약 설정 같은 실행 제어값은 비교에서 제외한다. 프리셋에 새 키가 추가된 경우는 허용한다.
- 후보가 정확히 하나면 ID 연결을 저장하고 변경 이력을 남긴다. 여러 후보, 불일치, 소유자 누락이면 자동 연결하지 않는다.
- 연결할 수 없는 기존 예약은 편집 화면에서 프리셋을 선택해 전환할 수 있게 한다. 기존 입력값 예약은 명시적으로 연결하기 전까지 호환 모드로 표시하고 보존한다. 삭제 후 재등록은 필요하지 않다.
- 이 전환은 재실행해도 결과가 중복되지 않아야 하며, 이미 연결된 ID를 재추정하지 않는다. 운영 DB를 직접 수정하는 임시 스크립트 대신 애플리케이션의 지속 가능한 전환 경로를 만든다.
- 애플리케이션 시작 때 전환하고, 전환 전에 즉시 실행 요청이 들어오더라도 실행 준비 단계에서 동일한 판정을 수행한다. 인증 입력이 없는 시스템은 프리셋 연결을 요구하지 않는다.

## 사용자 화면과 API

- 수트 예약 생성 요청은 선택한 프리셋 ID 맵을 전달한다. 단일 예약 생성도 선택한 프리셋 ID를 전달한다. 단일 폼에서 프리셋 선택 후 값을 직접 수정한 경우, 수정값을 프리셋에 저장하거나 별도 프리셋을 선택하도록 안내해 저장되지 않은 수정값이 사라지지 않게 한다.
- 예약 상세·편집에 연결된 프리셋 이름, 최신값 사용 안내, 연결 상태와 선택/교체 기능을 제공한다. 수트도 시스템별로 교체할 수 있다.
- 프리셋을 사용하지 않고 입력값을 직접 보내는 기존 API 요청은 호환한다. 연결된 예약의 입력값 수정은 프리셋 편집으로 안내하고, 참조와 직접 입력이 섞여 우선순위가 모호해지는 요청은 거부한다.
- API 응답·로그에 주민번호, 비밀번호, 전화번호 등의 인증값을 새로 노출하지 않는다. 참조 정보와 상태만 제공한다.
- 문서의 '저장된 인증 프리셋 유지' 표현은 실제 동작에 맞게 고친다.

## 구현 범위와 검증

예약 DTO·모델·서비스, 프리셋 조회 포트와 composition, API 오류 처리, 실행 화면·예약 편집 화면, 기존 예약 전환, 아키텍처·행동 Spec을 함께 변경한다. 신규 엔드포인트가 필요한지는 구현 계획에서 기존 API 확장 가능성을 우선 검토한다.

회귀 검증은 프리셋 수정 후 다음 실행 반영, 새 필드 반영, 수트/단일·cron/즉시/모바일 경로, 이미 시작된 실행의 입력 고정, 삭제·권한·잘못된 시스템 차단, 유일/모호/불일치 전환, 재시작 후 참조 유지, 프리셋 재선택 및 브라우저 모드 보존을 포함한다. 기존 관련 테스트와 문서 검사, 프론트 빌드 및 전체 CI 게이트를 실행한다. 실제 사이트에 OTP를 보내는 실행은 이 설계 검증에 필요하지 않다.

## 제외 범위

프리셋 수정 시 이미 진행 중인 실행의 입력을 바꾸는 기능, 삭제된 프리셋의 다른 프리셋 자동 대체, 예약 시스템·모듈 구성을 프리셋 변경에 따라 자동 변경하는 기능은 이번 범위에 포함하지 않는다.
