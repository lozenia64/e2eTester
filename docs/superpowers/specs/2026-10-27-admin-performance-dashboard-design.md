# 관리자 대시보드 성과 보고형 고도화 설계

작성일: 2026-10-27
상태: 사용자 승인 완료 — 구현·검증 완료
대상: 관리자 `/admin`
시각 기준: `research/admin-dashboard-concepts.html`의 ③ 성과 보고형

## 의도와 선택한 방향

임원이 첫 화면에서 자동 점검의 성과와 현재 품질을 파악하고 필요한 실행 결과로 이동하게 한다.
사용자는 세 가지 동작 목업을 비교한 뒤 **성과 보고형**을 선택했다.

| 검토 방향 | 장점 | 비용과 한계 | 결정 |
| --- | --- | --- | --- |
| 임원 브리핑형 | 당일 상태와 확인할 모듈이 즉시 보임 | 월간 업무 효과 설명이 약함 | 미선택 |
| 관제센터형 | 시스템 연결도와 운영 신호가 시연에 효과적 | 성과보다는 관제에 집중 | 미선택 |
| 성과 보고형 | 추정 절감 시간·추이·시스템별 기여로 자동화 효과 설명 | 월간 집계와 비교 기간 정의 필요 | 사용자 선택 |

이 문서의 상세 산정·구현 선택은 작성자의 제안이다. 목업의 수치와 문구는 실데이터에 맞춰 대체한다.

## 목표와 범위

- 월간 추정 절감 시간, 누적 추이, 시스템별 기여도를 화면의 중심에 둔다.
- 오늘의 모듈 통과율·확인할 모듈·7일 커버리지와 실제 실행 결과 이동을 유지한다.
- 초기 진입 모션과 데이터 변경 모션을 구별하고 접근성·성능·실패 상태를 함께 설계한다.
- 관리자 권한, 기존 통계와 상태 판정 정책을 그대로 사용한다.

전체 관리자 화면 리디자인, 일반 사용자 대시보드, 자동화 실행 변경, 테마 전환, PDF 보고서 생성은 범위 밖이다.
수치가 작다는 이유로 허구의 실적·전망을 넣거나, 추정 시간을 현금 절감액·직원 생산성으로 해석하지 않는다.

## 화면 구성

데스크톱은 목업의 밝은 바탕·청보라 성과 색상·큰 숫자·넓은 여백을 따른다. 기존 Pretendard와 디자인 토큰을 사용한다.
필요한 페이지 전용 의미 토큰은 기존 토큰 체계 안에서 정의한다. 공통 관리자 사이드바의 구조를 유지한다.

1. 제목·기준 월·마지막 갱신 시각·수동 새로고침. 월간 기준은 이번 달로 고정한다.
2. 월간 추정 절감 시간을 대형 숫자로 표시. 전월 동기간 비교와 산정 기준 진입을 제공한다.
3. 보조 지표: 이번 달 집계 대상 실행 수, 대상 시스템 수, 오늘 모듈 통과율, 오늘 확인할 모듈 수.
4. 왼쪽 누적 절감 추이, 오른쪽 시스템별 절감 기여. 막대는 절감 초 내림차순이며 모든 시스템을 표시한다.
5. 아래에 7일×3시간대 커버리지와 데이터 기반 관찰 요약.
6. 기존 오늘 시스템별 모듈 현황을 하단에 유지한다. 카드·커버리지 셀의 실제 실행 링크를 보존한다.

관찰 요약은 가장 큰 기여 시스템과 그 비중, 오늘의 이상/오류 모듈 수를 정해진 한국어 문장으로 표시한다.
합계가 0이면 기여율을 계산하지 않는다. AI 생성 요약이나 데이터로 입증할 수 없는 개선 평가는 넣지 않는다.
산정 기준은 접근 가능한 펼침 영역으로 설명하고 `/admin/modules`와 `/admin/stats`에 연결한다.
확인할 항목은 기존 일간 데이터의 모듈별 결과와 실행 ID를 이용해 실제 결과로 이동한다.

1440px 이상은 추이·기여도 2열, 768–1439px은 가용 폭에 맞춰 2열 또는 1열, 767px 이하는 1열이다.
본문 스크롤을 허용한다. 모바일에서 히트맵은 자기 영역의 가로 스크롤과 고정 시스템명 열을 사용한다.
페이지 전체의 가로 넘침은 허용하지 않는다. 색상만으로 상태를 설명하지 않으며 툴팁을 키보드로도 접근 가능하게 한다.

## 데이터와 산정 기준

### 현재 구현에서 재사용할 사실

- `StatsService.get_usage_stats`는 `StatsQueryPort`로 실행·모듈 이력 인덱스를 읽는다.
- 관리자 사용량 통계는 `ADMIN_VISIBLE_RUN_STATUSES` 대상 Run에 속한 PASSED 모듈의 기준 초만 합산한다.
- 기준 초는 manifest의 `estimated_manual_seconds`에 관리자 모듈 설정 override를 적용한다.
- ERROR/CANCELLED Run 제외 등 기존 통계 정책을 유지한다. 통계용 실행 수를 모든 실행 수로 오해하지 않도록 설명한다.
- 오늘 현황은 `/api/dashboard/daily`, 커버리지는 `/api/admin/dashboard`의 기존 계약을 따른다.

### 월간 성과 집계 제안

관리자 전용 `GET /api/admin/dashboard/performance`를 추가한다. 클라이언트에 개인별 사용자 통계나 Plotly figure를 보내지 않는다.
기간은 서버의 `Asia/Seoul` 달력 기준 이번 달 1일 00:00부터 한 번 캡처한 `generated_at`까지이다.
Run 귀속 일자는 기존 통계와 동일하게 `requested_at`의 한국 날짜를 사용한다. 미래 데이터는 제외한다.
절감 초는 합산 후 표시 단계에서만 시간으로 환산한다. 그래프 마지막 누적 초·시스템별 합계·주요 지표가 정확히 같아야 한다.

전월 비교는 전월 1일 00:00부터 같은 일자·시각까지이다. 전월에 해당 일자가 없으면 전월 말일까지를 대상으로 한다.
예: 3월 31일의 비교는 2월 전체, 10월 27일 09:42의 비교는 9월 27일 09:42까지다.
전월 합계가 0이면 비교율은 null이고 “비교할 전월 실적 없음”으로 표시한다. 0 나눗셈과 무한대 배지를 만들지 않는다.

응답은 생성 시각·타임존·양 기간 경계·이번 달/전월 절감 초·비교율·통계 대상 실행 수·시스템별 절감 초·일별 누적 초·산정 설명을 담는다.
일별 누적은 월초부터 오늘까지이며 실행이 없는 날은 직전 누적값으로 채운다. 미래 날짜까지 선을 연장하지 않는다.
월간 실행 수는 현재 통계의 집계 대상 완료 Run 수이며 UI 이름은 “이번 달 집계 실행”으로 한다.
대상 시스템 수와 오늘의 지표는 기존 일간 데이터에서 가져온다. 월간 그래프·배지는 서버 응답만 표시한다.

월간 읽기는 현재 달/전월의 범위 제한 이력 조회로 처리한다. 일자마다 별도 쿼리하거나 Run blob를 읽지 않는다.
사용량 통계와 새 성과 집계의 모듈 기준 시간 계산을 공유하는 내부 헬퍼로 추출해 중복 산식을 만들지 않는다.
기준 시간 설정을 바꾸면 과거 지표도 현재 기준으로 재계산됨을 산정 설명에 명시한다. 설정 이력 저장이나 DB 마이그레이션은 추가하지 않는다.
기준 초가 없거나 0인 모듈은 절감 합계에 0초를 기여한다. 정량 근거가 없으면 “산정 가능한 절감 시간 없음”과 기준 설정 링크를 보여준다.

오늘의 통과율은 기존 일간 데이터의 분모·분자를 그대로 사용하고 기준을 표시한다.
미점검·진행 중을 통과로 표시하지 않는다. 확인할 모듈은 일간 데이터의 anomaly+error 개수이며 과거 7일 셀 개수와 혼용하지 않는다.

## 구현 경계

- `app/contexts/insights/application/`: 월간 성과 집계, 기존 통계와 공유할 기준 초 계산.
- `app/core/stats_models.py`: 필요시 성과 응답 읽기 모델. 계약의 구체적인 클래스/헬퍼 이름은 계획 단계에서 확정한다.
- `app/api/routes_admin.py`: 관리자 권한 의존성을 사용한 새 읽기 API. 기존 API 응답을 변경하지 않는다.
- `app/web/templates/admin/index.html`: 목업 ③을 바탕으로 실제 데이터 표시 영역과 접근 가능한 로딩/오류 상태.
- `app/web/frontend/entries/admin-dashboard.ts` 및 인접 전용 모듈/스타일: 데이터 로드·차트·모션. 기존 JS의 히트맵·일간 이동 동작을 이관한다.
- `app/web/templates/admin/base.html`: 대시보드용 head asset 블록 추가가 필요한 경우만 수정한다.
- 기존 `app/web/static/admin-dashboard.js`는 새 엔트리 전환과 함께 참조를 제거한다. 다른 관리자 페이지의 통계 스크립트는 변경하지 않는다.
- 그래프는 이미 설치된 ECharts를 대시보드 엔트리에서 필요한 차트만 가져와 사용한다. 새 런타임 의존성·외부 CDN은 추가하지 않는다.
- API 문서는 `docs/E2E_ARCHITECTURE.md`, 행동/AC는 `docs/specs/insights/03-admin-stats.md`에 반영한다.

## 모션·상호작용

- 성공한 첫 데이터 수신 때만 숫자 약 1.1초 카운트업, 선 약 1.3초 그리기, 기여도 막대 약 0.9초 확장.
- 첫 렌더가 이미 정보 전달을 하도록 기본값을 숨기지 않는다. 차트 로드가 실패해도 합계와 시스템별 텍스트는 읽을 수 있다.
- 30초 갱신에서는 최초 등장 연출을 반복하지 않는다. 바뀐 수치/차트만 약 250ms 전환한다.
- `prefers-reduced-motion`에서는 카운트업·등장·그리기 모션을 생략한다. 의미 없는 무한 루프와 숫자 롤링은 없다.
- 차트는 컨테이너 크기에 맞춰 resize한다. 텍스트 요약과 접근 가능한 데이터 표/목록을 제공한다.
- 새로고침 중에는 중복 요청을 막고 탭이 숨겨지면 폴링을 멈춘다. 다시 보일 때 즉시 한 번 갱신한다.
- 성과·일간·커버리지 요청은 서로 독립적으로 성공/실패 처리한다. 갱신 실패 시 마지막 성공 데이터를 보존하고 “갱신 실패”와 해당 시각, 재시도를 제공한다.
- 최초 조회 실패, 정상적인 0 실적, 미점검, 아직 불러오는 중을 서로 구분한다. 실패를 0으로 덮지 않는다.

## 검증과 수용 기준

1. 동일 이력/설정에서 기존 사용량 통계와 성과 합계가 일치한다. 통과한 모듈만 포함하고 소수 분 단위 손실이 없다.
2. 월 경계·한국 자정·윤년/짧은 전월·전월 0·빈 기간·기준 초 0·설정 override·합계 정합성을 단위 테스트한다.
3. 관리자 API 인증/인가와 응답 계약을 검증한다. 기존 통계·커버리지·일간 테스트를 회귀 실행한다.
4. 프런트는 부분 실패·늦은 응답·중복 갱신·포커스 보존·최초 모션 1회·동작 줄이기를 검증한다.
5. 390px/768px/1440px/1920px에서 레이아웃을 확인한다. 실제 로컬 앱의 관리자 화면은 프로젝트 e2e-browser 순서로 검증한다.
6. 기존 히트맵 실행 링크·오늘 시스템 카드 링크·산정 기준 링크가 작동하고 모의 데이터가 제품에 남지 않는다.
7. 타입 검사·린트·빌드·관련 테스트·문서 정합성을 통과한다. PR 생성 전 전체 게이트를 백그라운드로 실행한다.

## 구현자가 정할 사항

구체적인 파일 분할·타입 이름·차트 축 간격·토큰의 정확한 값·일관된 빈 상태 아이콘은 기존 프로젝트 관례에 맞춰 정한다.
그래프의 장식보다 실수치의 가독성을 우선하며 목업의 전체 위계와 청보라 성과 색상을 유지한다.

## 설계 검토

별도 검토 에이전트가 구현 계획 수립에 필요한 미결 조건을 확인했다. 결과: 중요한 미결 질문 없음.
사용자 승인 후 Superpowers writing-plans로 구현 계획을 작성하고 실행한다.

## 구현 검증 결과

- `python scripts/ci/run_all_gates.py --profile full`: 16개 게이트 통과.
- Python 테스트 1,331개 통과·2개 건너뜀, Vitest 196개 통과. 기존 outbox hydration 테스트의 Pydantic 직렬화 경고 1개는 남아 있다.
- 별도 에이전트의 코드 검토와 후속 검토에서 중대·중요 결함 없음. 오류 안내·갱신 모션·빈 기여도 목록 전환을 회귀 테스트로 보완했다.
- Orca 브라우저에서 실제 DB 기준 3,674초가 월간 합계·시스템별 합계·누적 마지막 값·기존 통계와 일치했다.
- 390/768/1440/1920px 페이지 가로 넘침 없음. 모바일 히트맵 내부 가로 스크롤, 펼침 상태 보존, 실제 실행 링크, 부분 실패 시 데이터 보존 확인.
- 검증용 읽기 전용 서버는 `http://127.0.0.1:2223/admin`. 기존 2222 서버는 실행 중 Python 코드가 자동 재적재되지 않으므로 새 API 반영에 서버 재시작이 필요하다.
