# 상황판 리뉴얼 (Wall Renewal) — Design

**작성일:** 2026-08-24
**상태:** 초안 (사용자 리뷰 대기)
**대상:** `app/web/templates/wall_fragment.html`, `app/web/templates/wall.html`, `app/web/frontend/styles/wall.css`, `app/web/frontend/entries/wall.ts`, `app/web/frontend/styles/primitives.css`, `app/contexts/insights/application/wall_view.py`, `app/contexts/insights/application/daily_dashboard.py`

---

## 0. 요약

상황판(`/wall`)을 **암색 관제탑 + 오늘의 시간축**으로 재설계한다.

목표 감탄은 세 가지이고 각각 다른 장치가 담당한다.

| 감탄 | 담당 장치 |
| --- | --- |
| "살아있네" | 오른쪽 끝이 "지금" — 점검이 돌면 그 자리에서 새 스팬이 태어난다. morph 교체로 새 스팬만 등장 |
| "도시의 야경 같네" | 암색 바탕에 상태색이 발광 — 상시 디스플레이의 눈부심·번짐 문제도 함께 해결 |
| "이런 것까지 보이네" | 시스템 매트릭스가 **시간축의 y축으로 승격** — "언제, 어느 시스템에, 무슨 일이"가 한 형태에 |

## 1. 문제

### 1.1 걷어낼 잔재가 없다 — 이 작업은 순수한 격상이다

이 문서를 시작할 때의 전제는 "대시보드처럼 파이썬 잔재를 걷어내고 npm 을 도입한다"였으나, **실측 결과 상황판에는 해당 사항이 없다.**

| | 대시보드(이전) | 상황판(현재) |
| --- | --- | --- |
| 레거시 JS | `dashboard.js` 293줄 | 없음 — P3-2 에서 Vite/TS 로 신규 작성 |
| 이중 시스템 | JS 밀도 계산 + CSS 컨테이너 쿼리 | 없음 |
| 파이썬 잔재 | `plotly` → `plotly.js` 4.5MB 강제 | 없음 — 차트가 하나도 없다 |
| 번들 | 9.1MB | **7.1KB** (JS 0.2 + CSS 6.9) |

`wall_view.py` 134줄은 잔재가 아니라 **I/O 없는 순수 빌더**다. 서버가 읽기 모델을 만들고 Jinja 가 렌더하는 구조는 이 저장소의 의도된 설계이며 대시보드도 그대로 유지했다.

**따라서 예산 전부를 디자인에 쓴다.**

### 1.2 지금 화면은 정확하지만 정적인 문서다

현재 4층: 히어로(문장 1줄 + 상세 1줄) · 시스템 6칸(코드·막대·n/m·이름) · KPI 3장 · 메타 1줄.

- **스냅샷뿐이다.** "지금 상태"만 있고 "오늘 무슨 일이 있었나"가 없다.
- **15초마다 `hx-swap="outerHTML"` 로 본문 전체가 교체된다.** 대시보드가 morph 로 고친 그 문제와 같다. 조작이 없어 스크롤·포커스 손실은 없지만, 전체 교체는 모든 노드를 새로 만들어 **애니메이션을 매번 재시작**시킨다. "새 것만 등장하는" 연출이 구조적으로 불가능하다.
- **라이트 팔레트다.** 상시 디스플레이는 눈부심과 번인 때문에 거의 예외 없이 어두운 화면을 쓴다.

### 1.3 데이터가 이미 있다

깊이를 위해 신규 프로젝션이 필요 없다.

| 자산 | 내용 |
| --- | --- |
| `daily_system_status.updated_at` | 모듈별 마지막 상태 변경 시각 — **시스템별 점검 창을 여기서 유도한다** |
| `stats_rollup` / `rollup_between` | 일자별 카운트 (이번 범위 밖, 후속 후보) |
| `build_healing_metrics(trend_days=30)` | 30일 복구 추이 (이번 범위 밖) |

## 2. 실측이 설계를 바꿨다

시간축을 24시간으로 잡는 것이 자연스러워 보였으나, **실제 데이터가 그 안을 기각했다.**

`data/e2etester.db` 실측 (KST 2026-08-24):

| 시스템 | 모듈 | 점검 시각 | 소요 |
| --- | --- | --- | --- |
| HOM | 10 | 07:00 | 4분 25초 |
| FP | 3 | 07:11 | 1분 10초 |
| HWTC | 3 | 07:13 | 2분 4초 |
| CHBOT | 3 | 07:15 | 26초 |
| MHM | 8 | 08:02 | 6분 57초 |
| HRP | 4 | 08:24 | 1분 14초 |

**하루 Run 6개, 시스템당 1개, 전부 오전 07:00~08:25(85분)에 집중된다.**

24시간 축에 그리면:

- **94%가 빈 공간**이 된다
- CHBOT 의 26초 Run 은 폭 **0.03%** — 코앞에서도 보이지 않는다

기간별 Run 수도 확인했다(7~21건/일). 어느 날을 잡아도 아침 집중 패턴은 같다.

**결론: 축의 범위를 "오늘 첫 점검 → 지금"으로 압축한다.** 같은 데이터가 화면을 채우고, 시스템이 순서대로 점검되는 **계단 형태**가 드러난다 — 24시간 축에서는 절대 보이지 않던 정보다.

## 3. 목표 / 비목표 / 성공 기준

### 3.1 목표

1. 상황판이 **오늘의 흐름**을 3~5m 거리에서 형태로 읽히게 한다.
2. 상시 디스플레이에 맞는 **암색 팔레트**를 상황판 스코프로만 도입한다.
3. 교체를 morph 로 바꿔 **새로 생긴 것만 움직이게** 한다.

### 3.2 비목표 (명시적 YAGNI)

- **차트 라이브러리 도입** — 조작이 없는 화면이라 툴팁·줌·범례가 전부 사장된다. 서버 렌더 SVG + CSS 로 그린다(D2).
- **테마 축 신설** — 상위 설계 `2026-08-19` §2.2 의 "라이트 단일 팔레트" 결정은 인증 앱 화면에 대한 것이다. 상황판은 `base.html` 을 상속하지 않는 독립 문서이므로 **스코프 다크**로 충돌 없이 간다(D3).
- **JSON API 신설** — P3-2 D3 유지. 서버 렌더 HTML 만 낸다.
- **다음 예약 시각 표시** — 빈 상태에 넣고 싶었으나 기각. 비인증 페이지에 스케줄링 컨텍스트 의존이 하나 늘어나는 값에 비해 얻는 것이 작다(P3-2 "비인증 표면 최소화").
- **일자별 추이·복구 추이** — 데이터는 있으나 이번 축은 "오늘"이다. 후속 후보.
- **모듈 단위 점 31개** — 검토 후 기각(D4).

### 3.3 성공 기준

| 기준 | 측정 |
| --- | --- |
| 넌스크롤 | 1920×1080 · 2560×1440 에서 세로 스크롤바 0 |
| 암색 실적용 | `body.wall` 배경이 computed style 로 다크 |
| morph 교체 | 프래그먼트가 `hx-swap="morph:outerHTML"`, `outerHTML` 단독 0건 |
| 타임라인 정확도 | `build_timeline()` 단위 테스트 — 위치·폭·경계 |
| 빈 상태 | 오늘 점검 0건이면 축 대신 대기 문구 |
| 게이트 | `run_all_gates.py --profile full` 통과 |

## 4. 설계

### 4.1 레이아웃 — 4층에서 3층으로

```
┌──────────────────────────────────────────────────────────┐
│  오늘 점검은 정상                        2026-08-24      │ ① 지배 상태
│  27/31 모듈 · 07:00 → 08:25                갱신 08:25   │
├──────────────────────────────────────────────────────────┤
│  HOM  ▓▓▓▓▓░                                             │
│  FP        ▓▓                                            │ ② 타임라인
│  HWT        ▓▓▓                                          │   시스템 = y축
│  CHB         ▓                                           │   시간   = x축
│  MHM                        ▓▓▓▓▓▓▓▓                     │
│  HRP                                          ▓▓  ┃지금  │
│       07:00    07:20    07:40    08:00    08:25          │
├──────────────────────────────────────────────────────────┤
│  ┌─────────┐ ┌─────────┐ ┌─────────┐                    │ ③ KPI 3장
│  │   4     │ │   2     │ │  31h    │                    │
│  │스스로복구│ │승인 대기│ │이번달절감│                    │
│  └─────────┘ └─────────┘ └─────────┘                    │
└──────────────────────────────────────────────────────────┘
```

**층이 4개에서 3개로 줄면서 정보량은 늘어난다.** 기존 시스템 매트릭스(코드·막대·n/m·이름)가 타임라인의 y축으로 흡수되기 때문이다.

**① 지배 상태** — `wall_view.py` 의 `_dominant()` 를 그대로 쓴다. 헤드라인·상세 생성 규칙을 손대지 않고 우측에 날짜·갱신 시각을 붙인다. `waiting_input` 지배 시 히어로 전체가 맥동하는 기존 결정(`wall.css` 현행, P3-2 §3.10)을 유지한다.

**② 타임라인** — 시스템 6행. 각 행의 스팬은 **그 시스템 모듈들의 `updated_at` 최소~최대**다. 스팬 색은 기존 `_system_tone()` 재사용. 실패 모듈이 있으면 스팬 안에 해당 구간만 다른 색 조각으로 넣는다 — 모듈 단위 정보를 형태를 흐리지 않고 흡수하는 방법이다.

**③ KPI 3장** — 기존 `kpi_card` 매크로를 `size="lg"` 로 그대로 호출한다. **매크로 시그니처를 건드리지 않는다**(대시보드와 공유 — 대시보드 작업의 D2 와 같은 이유).

**빈 상태** — 오늘 점검이 0건이면 타임라인 자리에 "오늘 점검 대기 중"을 크게 표시한다. 축을 억지로 그리지 않는다.

### 4.2 암색 팔레트

| 축 | 방식 |
| --- | --- |
| 상태색 | `--st-*-solid` **그대로 재사용**. 어두운 바탕에서 발광색으로 작동한다. SSOT 재생성 불필요 |
| `--st-*-surface/text/border` | **쓰지 않는다** — 밝은 배경 전제로 계산된 값이다 |
| 중립색 | `primitives.css` 에 다크 램프를 신규 primitive 로 추가하고 `wall.css` 가 `--wl-*` 로 매핑 |

**FG-002 가 이 경로를 강제한다.** `frontend/` 안에서 hex 를 쓸 수 있는 곳은 `primitives.css` · `tokens.generated.css` · `status.generated.ts` 뿐이다. 다크 중립색을 `wall.css` 에 직접 박으면 게이트가 막는다.

```css
/* primitives.css — 신규 다크 램프(상황판 전용) */
--c-ink-950: #0b0e14;   /* 바탕 */
--c-ink-900: #111622;   /* 트랙·카드 표면 */
--c-ink-800: #1c2230;   /* 경계선 */
--c-ink-400: #8b93a7;   /* 흐린 글자 */
--c-ink-100: #e7e9ee;   /* 본문 글자 */
```

`#0b0e14` 바탕 기준 명암비 실측:

| 대상 | 명암비 | 판정 |
| --- | --- | --- |
| `--c-ink-100` 본문 | **15.90:1** | AAA |
| `--c-ink-400` 흐린 글자 | 6.28:1 | AA |
| `--st-passed-solid` | 7.61:1 | AAA(대형) |
| `--st-anomaly-solid` | 8.99:1 | AAA(대형) |
| `--st-running-solid` | 5.25:1 | AA |
| `--st-error-solid` | 5.13:1 | AA |
| `--st-waiting_input-solid` | 4.56:1 | AA |

전부 AA 이상이다. 3~5m 거리에서는 이 여유가 필요하다.

### 4.3 데이터 경로 — 백엔드 변경이 파일 하나에 갇힌다

현재 흐름:

```
daily_system_status ─→ build_daily_dashboard_from_projection ─→ dashboard dict
                                                                     │
       daily_summary_queries: totals·date_label·generated_at·attention·systems 복사
                                                                     │
                                                          build_wall_view(summary)
```

`wall_view.py` 는 이미 `summary["systems"]` 를 읽는다. **시스템 뷰에 시각 정보만 실으면 나머지 경로는 그대로 흐른다.**

`app/contexts/insights/application/daily_dashboard.py` 만 고친다:

| 변경 | 내용 |
| --- | --- |
| `_module_view_from_row` | `"at_iso"` 필드 추가 — `status_row.updated_at.astimezone(tz)` |
| `_system_view_from_projection` | 모듈들의 `at_iso` 로 `first_at` · `last_at` 계산해 시스템 뷰에 추가 |

`daily_summary_queries.py` 는 **손대지 않는다** — `systems` 를 통째로 복사한다.

`wall_view.py` 에 순수 함수를 하나 더한다:

```python
def build_timeline(systems: list[dict], *, now_iso: str) -> dict[str, Any]
# → {"origin": "07:00", "now": "08:25", "span_minutes": 85,
#    "lanes": [{"code": "hom", "name": "HOM", "tone": "error",
#               "left_pct": 0.0, "width_pct": 5.2}, ...],
#    "ticks": [{"label": "07:00", "left_pct": 0.0}, ...]}
```

**x% 계산이 순수 함수라 단위 테스트가 쉽다.** 서버 렌더를 고른 부수 효과다.

경계 조건은 함수가 직접 처리한다:

- 오늘 점검 0건 → `lanes` 빈 리스트, 호출부가 빈 상태를 렌더
- 시스템 1개뿐이라 `span_minutes == 0` → 0 나눗셈 없이 폭 100%
- `first_at > last_at`(시계 역전) → 스팬 폭 최소값으로 잘라 그린다
- **최소 창 길이 30분** — 전 시스템이 몇 분 안에 끝나면 창이 그만큼 압축돼 스팬이
  화면을 가득 채운다. 창 길이가 30분 미만이면 30분으로 늘려 잡는다.
  근거: 실측 최장 Run 이 6분 57초이므로 30분이면 가장 긴 Run 도 폭 23% 이하로
  들어오고, 시스템 간 간격도 남는다.
- **최소 스팬 폭 0.8%** — 26초짜리 Run 이 85분 창에서 폭 0.5% 로 사라지는 것을 막는다.
  1920px 화면에서 약 15px 로, 3~5m 거리에서 인지 가능한 하한이다.

### 4.4 갱신과 모션

**`idiomorph` 를 상황판에 도입한다.** 이번 작업에서 유일하게 추가되는 npm 라이브러리이며, 대시보드 작업으로 **이미 저장소 의존성이라 신규 패키지는 0개**다.

| 계층 | 장치 |
| --- | --- |
| 교체 | `hx-ext="morph"` 를 `<body class="wall">` 에(교체 대상 **바깥**), 프래그먼트는 `hx-swap="morph:outerHTML"` |
| 진입 | 새 스팬만 `@starting-style` 로 좌→우 wipe |
| 지속 | "지금" 마커 맥동 · `running` 스팬 shimmer |
| 주의 | `waiting_input` 지배 시 히어로 전체 맥동 — 기존 결정 유지 |
| 정지 | `prefers-reduced-motion: reduce` 에서 전부 정지 |

`hx-ext` 를 body 에 두는 이유: 프래그먼트 자신이 `outerHTML` 로 교체되므로, 확장 선언이 교체 대상 안에 있으면 첫 교체 후 사라진다.

폴링 주기 15초는 그대로 둔다. 조절 필요가 확인되지 않았다.

| **D2** | **차트 라이브러리를 쓰지 않는다.** 서버 렌더 SVG + CSS | 조작이 없어 라이브러리 가치의 대부분이 사장된다. 현재 번들 7.1KB 를 지키고, JS 가 죽어도 화면은 남는다 — 무인 구동에서 큰 미덕. 사용자 결정 |
| **D3** | **상황판만 다크.** 테마 축을 만들지 않는다 | `base.html` 을 상속하지 않는 독립 문서라 스코프 격리가 공짜다. 다른 화면·메일에 영향 0. 사용자 결정 |
| **D4** | 타임라인 단위는 **시스템 스팬**(모듈 점 31개 아님) | 모듈은 Run 안에서 몇 초 간격으로 끝나 거의 붙어 보인다(CHBOT 3개가 26초 안에). 정보는 늘지만 3~5m 에서 형태가 흐려진다. 모듈 정보는 스팬 내부 색 조각으로 흡수 |
| **D5** | x축 범위를 **오늘 첫 점검 → 지금**으로 압축 | 24시간 축은 실측상 94%가 빈 공간이고 26초 Run 이 폭 0.03% 가 된다. 대가(눈금이 매일 달라짐)는 축 라벨로 흡수 |
| **D6** | KPI 3장 **유지** | 절감·복구·승인 대기는 상황판의 존재 이유 중 하나다. 사용자 결정 |
| **D7** | 빈 상태에 **다음 예약 시각을 넣지 않는다** | 비인증 페이지에 스케줄링 의존이 하나 늘어난다. P3-2 의 비인증 표면 최소화 원칙 |

새로 붙일 검증:

| 대상 | 도구 | 확인 |
| --- | --- | --- |
| `build_timeline()` | pytest | 위치·폭 계산 · 단일 시스템(폭 0 분모) · 점검 0건 · 시각 역전 방어 |
| 빈 상태 | pytest | 점검 0건이면 lanes 비고 대기 문구 |

| **다크 실적용** | Playwright | `body.wall` 배경이 computed style 로 다크 |
| 넌스크롤 | Playwright | 1920×1080 · 2560×1440 세로 스크롤 0 |

**computed style 단언을 처음부터 넣는다.** 대시보드 작업에서 컴포넌트 CSS 가 아예 로드되지 않는데 빌드·타입체크·린트·게이트·Playwright 가 전부 통과한 사고가 있었다. 상황판은 `wall.html:10` 이 `asset_styles("entries/wall.ts")` 를 이미 렌더하므로 같은 결함은 없지만, DOM 존재만 보는 단언은 이 유형을 영원히 못 잡는다.

기존 테스트 `tests/test_wall_view.py`(287줄) · `tests/test_wall_http.py`(237줄)는 **삭제하지 않고 새 계약으로 갱신**한다.

## 7. 리스크 · 한계

| 항목 | 내용 | 대응 |
| --- | --- | --- |
| **압축축 눈금이 매일 달라진다** | 어제와 오늘의 x축 범위가 다르다 | 절대 시각을 눈금 라벨로 항상 표시한다. 상황판은 "오늘"만 보는 화면이라 날짜 간 비교 용도가 아니다 |
| **모든 시스템이 동시에 돌면 계단이 사라진다** | 스팬이 전부 겹쳐 한 덩어리로 보인다 | 시스템별 행이 분리돼 있어 겹쳐도 각자 읽힌다. 형태가 "계단"에서 "블록"으로 바뀔 뿐 정보 손실은 없다 |
| **점검 창이 매우 짧으면 스팬이 과대 표현된다** | 전 시스템이 1분 안에 끝나면 창이 1분으로 압축돼 스팬이 화면을 가득 채운다 | §4.3 의 **최소 창 길이 30분**이 막는다 |
| **아주 짧은 Run 이 보이지 않는다** | 26초 Run 은 85분 창에서 폭 0.5% | §4.3 의 **최소 스팬 폭 0.8%**(1920px 에서 약 15px)로 하한을 둔다 |
| **`updated_at` 은 모듈의 마지막 변경 시각이다** | 같은 모듈이 하루에 여러 번 돌면 마지막만 남는다 | 현 운영은 시스템당 하루 1 Run 이라 실질 영향이 없다. 다중 Run 이 일상화되면 `run_history_index` 기반으로 승격한다(후속) |
| **다크 전환이 상황판만이라 두 화면이 이질적** | 대시보드와 나란히 걸면 톤이 다르다 | D3 의 의도된 절충. 상시 디스플레이와 업무 화면은 맥락이 다르다. 사용자 확인 완료 |
