# 관리자 사용자 관리 리뉴얼 설계

2026-10-29 사용자가 `research/admin-users-renewal-mockup.html` 목업을 승인하고 실제 구현을 요청했다.

## 구성과 범위

기존 관리자 셸 안에 밝은 바탕·인디고 강조의 사용자 목록 + 우측 상세 패널을 배치한다. 상단 전체·활성·관리자 수, 이름/이메일 검색, 전체/활성/비활성 필터, 아바타와 이름·이메일을 묶은 행을 제공한다. 행 선택 시 계정 정보·접근 범위·시스템 체크 목록을 표시한다. 추가는 모달, 활성/비활성·삭제는 더보기, 권한 저장은 패널 하단에 둔다. 좁은 화면에서는 목록 아래에 상세 패널을 배치한다. 사이드바·다른 관리자 페이지는 변경하지 않는다.

## 접근법

단순 테이블 정돈, 사용자 카드, 목록+상세 패널 중 사용자가 마지막 구성을 승인했다. 기존 API를 유지하고 Jinja 템플릿과 전용 Vite TypeScript/CSS 엔트리로 구현한다. 목업의 예시 데이터와 셸은 제품 코드로 복사하지 않는다.

## 기존 동작과 연결

GET/POST `/api/admin/users`, PATCH `/api/admin/users/{id}/active`, DELETE `/api/admin/users/{id}`, GET `/api/admin/systems`, PUT `/api/admin/users/{id}/systems`를 유지한다. 관리자 접근 권한은 항상 전체이며 체크 편집은 읽기 전용으로 표시한다. 기존 활성/삭제 기능은 관리자 계정에도 유지하고, 요청 전 확인을 받는다.

일반 사용자의 `allowed_system_codes=[]`는 실제 API/대시보드에서 접근 없음이다. 예전 화면의 ‘미선택=전체’ 안내는 잘못됐다. ‘전체 시스템’은 현재 등록된 코드 전체를 명시적으로 저장하며 향후 등록되는 시스템을 자동 부여하지 않는다. 선택 모드에서 0개를 저장하면 접근 없음이다. 미등록 기존 코드는 별도 이름으로 표시하고 명시적으로 해제하기 전까지 보존한다. 사용자 생성 직후 일반 계정은 접근 없음으로 표시해 설정을 유도한다. 백엔드 정책은 변경하지 않는다.

## 검증 기준

검색·필터와 집계 수치, 선택 전환, 미저장 변경 취소/유지, 저장 중 중복 요청 방지, API 실패 후 재시도와 초안 유지, 시스템 조회 실패 시 편집 잠금, 빈 목록, XSS 방지, 키보드·모바일 사용을 검증한다. 실제 사용자 데이터를 변경하는 브라우저 검증은 하지 않고 변경 API는 테스트 대역으로 확인한다.
